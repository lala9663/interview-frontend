# API 계약 바꾸기

계약 문서는 세 레포에 같은 내용으로 들어 있다: 각 레포의 `docs/contract/api-contract.md`. 한 레포만 고치면 나머지와 어긋난다.

## 절차
1. **바꿀 내용을 한 문단으로 적는다**: 무엇을(경로·필드·이벤트·열거형), 왜, 어느 레포가 영향받는지.
2. **호환되게 바꿀 수 있는지 본다.** 될 수 있으면 "더하기"로 한다.
   - 필드 추가(선택 값) → 호환. 받는 쪽은 없는 필드를 견뎌야 한다.
   - 필드 이름 변경·삭제, 열거형 값 삭제, 필수 값 추가 → 깨짐. 꼭 필요하면 "새 필드 추가 → 세 레포 전환 → 옛 필드 삭제" 두 단계로 한다.
3. **이 레포의 `docs/contract/api-contract.md`를 고친다.** 표와 JSON 예시를 둘 다.
4. **이 레포의 코드를 맞춘다**:
   - REST: `src/api/index.js`, `src/mocks/server.js`, 쓰는 화면
   - WebSocket 이벤트: `src/features/room/room-state.js`(+ `room-state.test.js`), `src/mocks/socket.js`
   - 열거형: `src/lib/labels.js`
5. **PR 설명 맨 위에 `[계약 변경]`을 적고**, 고친 계약 문서의 diff를 그대로 붙인다. 다른 두 레포 담당자가 같은 diff를 자기 레포의 `docs/contract/api-contract.md`에 반영하고 코드를 맞춘다.
6. 세 레포의 PR은 같은 날 합친다. 순서는 "받는 쪽 먼저, 보내는 쪽 나중"(새 필드를 견디는 쪽이 먼저 나가야 한다).

## 혼자 세 레포를 다 볼 수 있을 때
세 레포가 같은 상위 폴더에 있으면 계약 파일 세 개를 한 번에 같은 내용으로 고치고, 레포마다 PR을 만든다. 세 파일의 내용이 같은지 마지막에 비교한다.

## 하지 말 것
- 화면에 필요하다고 mock에만 필드를 더하기(실서버에 붙이면 깨진다)
- 계약 문서를 안 고치고 코드만 바꾸기
