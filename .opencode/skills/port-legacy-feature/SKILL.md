# 기존(레거시) 프로젝트의 기능 가져오기

기존 프로젝트는 지금 구조와 **비슷하지만 다르다**: 백엔드가 Python 하나였고(지금은 Java 백엔드 + Python Agent), 화면 스택도 다를 수 있다(TypeScript, 다른 UI 라이브러리, 다른 API 모양). **파일을 복사하지 않는다. 동작을 이해하고 이 구조에 맞게 다시 쓴다.**

## 1단계: 기존 기능을 읽고 한 장으로 적는다
기존 코드에서 그 기능에 해당하는 것을 찾아 아래를 채운다(추측하지 말고 코드에서 확인).
- 사용자가 보는 것: 어느 화면, 어떤 조작, 어떤 결과
- 화면이 부르는 API: 경로, 요청·응답 필드
- 서버가 하는 일: 저장하는 것, 권한 검사, 업무 규칙, AI 호출(프롬프트·모델), 음성 처리
- 실시간 요소: 소켓·SSE 이벤트
- 설정값과 외부 연동

## 2단계: 세 레포로 나눈다
| 기존 코드에서 하던 일 | 지금 넣을 곳 |
| --- | --- |
| 화면, 입력 검증(편의), 표시 형식 | **frontend** (여기) |
| DB 저장·조회, 권한, 상태 전이, 엑셀·파일, 작업 관리 | **backend** (`interview-backend`) |
| LLM 호출, 프롬프트, STT·오디오, 화자 판정, 질문 매칭 | **agent** (`interview-agent`) |
| 화면이 Python 서버를 직접 부르던 AI 기능 | backend가 받아서 agent를 부른다(프론트는 backend만 안다. 예외: 면접 방 WebSocket) |

기능 하나가 세 레포에 걸치면 레포마다 작업을 나누고, 사이를 잇는 계약을 먼저 정한다(skill `change-api-contract`). 다른 두 레포의 `port-legacy-feature` skill에 각자의 절차가 있다.

## 3단계: 이미 있는지 확인한다
같은 기능이 이름만 다르게 이미 있을 수 있다. 아래에서 찾아본다.
- `README.md`의 화면 표, `src/router/index.js`
- `docs/contract/api-contract.md`의 엔드포인트
- 상위 `docs/07-legacy-porting-guide.md`의 "기존 기능 ↔ 지금 위치" 표

있으면 새로 만들지 말고 **차이만** 더한다. 기존 방식과 지금 방식이 충돌하면(예: 기존은 AI 점수를 합산, 지금은 참고용으로 분리) 지금 방식을 유지하고, 요청자에게 차이를 알린다.

## 4단계: 프론트 몫을 옮긴다
1. API가 필요하면 계약에 더하고 `add-api-call` 절차대로 `api/index.js` + `mocks/server.js`.
2. 화면은 `add-screen` 절차대로 `features/<기능>/`에 **다시 쓴다**. 기존 코드에서 가져오는 것은 동작과 문구이고, 바꾸는 것은 다음이다.
   | 기존 | 지금 |
   | --- | --- |
   | TypeScript (`.ts`, `lang="ts"`, 타입·인터페이스) | JavaScript. 타입 표기를 지우고 모양은 계약 문서를 따른다 |
   | 다른 UI 라이브러리(shadcn-vue, reka-ui, Element 등) | `styles/main.css`의 공용 클래스와 `components/`의 것 |
   | 데이터 라이브러리(vue-query 등) | `api` 함수 + `ref` + `usePolling` |
   | 직접 색, 자체 CSS 파일 | 색 토큰 |
   | 그 프로젝트의 API 필드 이름(snake_case 등) | 계약의 camelCase |
   | SSE(EventSource) 실시간 | 면접 방 WebSocket 이벤트(`work-on-live-room`) |
3. 새 npm 패키지를 가져오지 않는다. 꼭 필요하면 사내 미러에 있는지 확인하고 이유를 PR에 적는다.
4. 기존 화면의 문구·단축키·빈 화면 안내처럼 사용자가 익숙한 것은 살린다.

## 5단계: 확인하고 기록한다
- mock으로 화면 확인(1366×768, 어두운 화면), `npm run check`.
- 상위 `docs/07-legacy-porting-guide.md`의 "기존 기능 ↔ 지금 위치" 표에 한 줄을 더한다(무엇을 가져왔고 무엇을 다르게 했는지).
- 가져오지 않기로 한 부분은 이유와 함께 PR에 적는다.

## 가져오면 안 되는 것
- 기존 프로젝트의 로그인·토큰 처리(지금은 백엔드 JWT + AD SSO)
- 지원자 개인정보를 브라우저에 오래 저장하는 코드(`localStorage`)
- 화면에서 AI 서버·모델을 직접 부르는 코드
- 블라인드 항목(성별, 가족 등)을 화면에 보여 주는 코드
