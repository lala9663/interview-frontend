# 면접 방(실시간) 고치기

## 먼저 읽을 것
- `docs/realtime-room.md` (두 배치, 흐름, 실시간 기능이 잠긴 면접, 질문과 꼬리질문 나무, 끊겼을 때, 단축키, 화면 규칙)
- `docs/contract/api-contract.md` 3장 (WebSocket 메시지)

## 구조 요약
`RoomPage.vue`(틀·단축키·실시간 기능 잠금) → `use-room.js`(데이터·소켓·재연결) → `room-state.js`(이벤트를 상태로, 질문과 꼬리질문을 나무로 묶는 `questionTree`. 순수 함수) / `use-microphone.js`(마이크 → PCM16) / 칸 컴포넌트.

기본 배치(`lib/features.js`의 `feedback1118`이 켜졌을 때: `npm run dev`, `npm run dev:api`, 배포 빌드, 4주 차 이후 목업):

| 자리 | 컴포넌트 | 보이는 것 |
| --- | --- | --- |
| 왼쪽 | `CandidateBrief.vue` + 메모 | 지원자 요약(요약·확인할 점·이력 탭)과 내 메모 |
| 가운데 | `QuestionTreePane.vue` | 질문(줄기)과 꼬리질문(가지) 나무, 아래에 "방금 들은 말" 한 줄 |
| 오른쪽 | `TranscriptPane.vue` | 대화. 접혀 있고 "대화 펼치기"를 눌러야 열린다 |

- 가지는 세 가지다: 면접 전에 만든 예상 꼬리질문(`parentQuestionId`), 면접 중 제안된 꼬리질문(`followup.suggested`), 채택한 꼬리질문. 어느 질문 아래에 붙는지는 `questionTree(questions, followUps, utterances)`가 정한다. 나무의 동작을 바꾸면 `room-state.test.js`의 나무 테스트를 같이 고친다.
- 실시간 기능이 잠긴 방: `liveLocked(interview)`(`lib/features.js`)가 참이면(면접 응답의 `liveEnabled`가 `false`. 신입은 백엔드 기본 설정이 그렇다) 입장권·소켓·마이크를 쓰지 않고 질문 화면으로만 쓴다. 왼쪽·가운데 두 칸뿐이다. 화면은 트랙이나 환경변수를 보지 않는다.
- 예전 배치(왼쪽 `QuestionPane.vue`, 가운데 대화, 오른쪽 `AssistPane.vue`)는 `feedback1118`이 꺼지는 3주 차 목업에서만 쓰인다.

## 새 서버 이벤트를 화면에 반영하기
1. API 명세 3.2에 이벤트가 있는지 확인(없으면 skill `change-api-contract`).
2. `room-state.js`
   - 필요한 상태를 `createRoomState()`에 더한다.
   - `applyEvent`의 `switch`에 `case`를 더한다. **여기서는 네트워크·DOM·타이머를 쓰지 않는다.**
3. `room-state.test.js`에 그 이벤트의 테스트를 더한다(순서가 바뀌어 오거나 두 번 와도 괜찮은지 포함).
4. `mocks/socket.js`가 같은 이벤트를 내보내게 해서 `npm run dev`에서 볼 수 있게 한다.
5. 칸 컴포넌트에서 `state`를 그린다. 질문·꼬리질문에 관한 것이면 `QuestionTreePane.vue`, 발화에 관한 것이면 `TranscriptPane.vue`와 `RoomPage.vue`의 "방금 들은 말" 줄이다. 실시간 기능이 잠긴 방에는 이벤트가 오지 않는다.
6. 이벤트를 받고 **저장까지 해야 하면**(백엔드 호출) `room-state.js`가 아니라 `use-room.js`의 `onEvent`에서 한다. 예: `followup.matched`(면접관이 제안된 꼬리질문을 말로 물음) → `room-state.js`는 `spoken` 표시만 남기고, `use-room.js`의 `onFollowUpSpoken`이 누른 것과 같이 질문 목록에 올리고 "물음"으로 표시한다.
   - 이벤트는 방의 모든 단말에 간다. 저장은 **마이크를 보내는 단말 하나만** 한다(`audioOwner`). 나머지 단말은 표시만 바꾸고 잠시 뒤 목록을 다시 읽는다. 모두가 저장하면 같은 질문이 여러 번 생긴다.

## 새 클라이언트 메시지를 보내기
`use-room.js`에 동작 함수를 더하고(`send({ type: '…' })`), 화면은 그 함수를 부른다. 화면을 먼저 바꾸고(낙관적 갱신) 서버가 같은 내용을 이벤트로 돌려주면 덮어쓰이게 한다. `mocks/socket.js`의 `send`에도 처리 한 줄.

면접 중에 질문을 더하는 동작(직접 추가, 꼬리질문 채택)은 끝에 `send({ type: 'question.added', questionId })`를 보낸다. Agent가 질문 목록을 다시 읽어, 그 질문도 말로 물으면 알아보게 하기 위해서다.

## 지켜야 할 것
- **면접이 멈추면 안 된다.** 소켓·STT·LLM이 실패해도 화면은 계속 쓸 수 있어야 한다(메모, 질문 표시). 오류는 위쪽 노란 줄에 문장으로 알린다.
- **seq로만 순서를 판단한다.** 이벤트는 늦게, 겹쳐, 순서가 바뀌어 올 수 있다. `upsertUtterance`를 쓴다.
- **페이지 스크롤 금지.** 1366×768에서 페이지 스크롤이 없어야 한다(대화를 접은 두 칸, 펼친 세 칸 모두). 칸이 각자 스크롤한다. 칸을 더하지 말고 기존 칸 안에 넣는다.
- **오디오 형식 고정**: 16kHz, 모노, PCM 16비트 리틀엔디언. `public/audio/pcm16-worklet.js`는 import 없는 단독 파일이어야 한다.
- 나무에서는 줄기 질문의 글자가 가장 크고 가지는 그보다 작다. 대화에서는 지원자 답변 글자가 가장 크다.
- **대화는 접힌 것이 기본이다.** 접혀 있어도 "방금 들은 말" 줄로 전사가 들어오는 것을 알 수 있어야 한다.
- **잠금은 `liveLocked(interview)`로만 판단한다.** 잠긴 방에서 입장권을 요청하거나(백엔드가 `409 LIVE_DISABLED`로 답한다) 소켓·마이크를 여는 코드를 더하지 않는다.
- 단축키는 입력 칸에 초점이 있을 때 동작하면 안 된다(`RoomPage.vue`의 `onKey`).
- **자동으로 잡힌 것은 되돌릴 수 있어야 한다.** 말로 인식해 "물음"·채택이 된 것은 틀릴 수 있다(글자 겹침 기준이라 비슷한 다른 질문이 잡힐 수 있다). 질문을 다시 누르면 풀리는 동작을 깨지 않는다.

## 확인
- `npm run dev` → 오늘 화면에서 경력 화상 직무 면접(`mocks/data.js`의 `interviews`에서 면접자 201의 `JOB` 면접. 대본은 `liveScriptExperienced`) → 면접 방 입장 → 면접 시작.
  - 왼쪽에 지원자 요약과 메모, 가운데에 질문 나무가 보이고 대화는 접혀 있는지. "방금 들은 말" 줄에 전사가 흐르는지.
  - 물은 질문에 "물음"과 "지금 질문" 표시가 붙고, 제안된 꼬리질문이 그 질문 아래 가지로 붙는지.
  - 대본 6번째 말(면접관이 "멱등 처리는 구체적으로 어떻게 구현했나요"를 말로 물음)에서 그 제안이 누르지 않아도 채택된 가지로 바뀌는지. 그 답에서 나온 제안이 그 꼬리질문 아래에 한 단계 더 들여 쓰이는지.
  - 준비한 순서와 다르게 묻는 장면(질문 4를 질문 3보다 먼저)에서 앞서 붙은 가지의 자리가 바뀌지 않는지.
  - "대화 펼치기"를 누르면 오른쪽에 대화가 열리고, 1366×768에서 페이지 스크롤이 생기지 않는지.
- 면접 종료 → 평가 화면에서 초안 보고서 → 약 12초 뒤 보정본으로 바뀌는지.
- 실시간 기능이 잠긴 방: 신입 면접에 들어가 "실시간 기록 잠김" 배지가 보이고, 마이크·연결 표시·"대화 펼치기"·"꼬리질문 지금 만들기"가 없고, 질문 아래에 예상 꼬리질문 가지가 보이고, 종료 확인 창이 보고서를 만들지 않는다고 알리는지.
- 실제 Agent로는 `npm run dev:api`. 마이크 권한을 허용하고 말해 본다.
- `npm run check`.
