# 면접 방 (면접 중 화면)

> 다루는 것: `features/room`이 마이크·Agent·백엔드와 어떻게 이어지는가, 끊겼을 때 어떻게 되는가.
>
> 이벤트 모양은 [contract/api-contract.md](contract/api-contract.md) 3장이 원본이다.

## 배치가 두 가지다

`RoomPage.vue`는 `lib/features.js`의 `feedback1118` 스위치에 따라 두 배치 가운데 하나를 그린다. 마이크·소켓·상태(`use-room.js`, `room-state.js`의 `applyEvent`)는 두 배치가 같이 쓴다.

| | `feedback1118`이 켜졌을 때 | `feedback1118`이 꺼졌을 때 |
| --- | --- | --- |
| 어느 빌드 | `npm run dev`, `npm run dev:api`, 배포 빌드, 4주 차 이후 목업 | 3주 차 목업 |
| 왼쪽 | 지원자 요약(`CandidateBrief.vue`: 요약·확인할 점·이력 탭)과 내 메모 | 지원자 요약(접는 한 덩어리)과 질문 목록(`QuestionPane.vue`) |
| 가운데 | 질문과 꼬리질문 나무(`QuestionTreePane.vue`), 아래에 "방금 들은 말" 한 줄 | 대화(`TranscriptPane.vue`) |
| 오른쪽 | 대화(`TranscriptPane.vue`). 접혀 있고 "대화 펼치기"로 연다 | 꼬리질문·메모(`AssistPane.vue`) |
| 신입(대면) 면접 | 면접의 `liveEnabled`가 `false`면 실시간 기능 잠금(아래 "실시간 기능이 잠긴 면접") | 모의 서버가 `liveEnabled: true`를 줘 잠기지 않는다 |

스위치가 어느 빌드에서 켜지는지는 [setup.md](setup.md)의 "가짜 데이터로 돌 때만 켜지는 화면".

## 들어와서 나갈 때까지

1. `POST /interviews/{id}/room` — 방을 얻는다(없으면 만든다). 질문·저장된 전사·꼬리질문을 읽는다.
2. 방이 `CREATED`면 "면접 시작" 덮개. "이 노트북의 마이크를 사용"을 끄면 듣기 전용 단말이 된다.
3. "면접 시작" → `POST /rooms/{id}/start` → `POST /rooms/{id}/ticket { audio }` → 응답의 `agentWsUrl`로 WebSocket 연결 → 첫 메시지 `{ type: "auth", ticket }`.
4. 마이크 단말은 100ms마다 PCM16(16kHz 모노) 바이너리 프레임을 보낸다.
5. Agent 이벤트를 `applyEvent`가 상태에 반영한다: `transcript.partial`(임시 글자) → `transcript.final`(다듬은 문장 + 화자) → `question.matched`(질문에 "물음" 표시) → `followup.suggested`(꼬리질문 후보) → `followup.matched`(면접관이 꼬리질문 후보를 말로 물음. `use-room.js`가 누른 것과 같이 질문 목록에 올리고 "물음"으로 표시한다. 저장은 마이크를 보내는 단말만 한다).
6. "면접 종료" → 메모를 마지막으로 저장 → `POST /rooms/{id}/end` → 평가 화면으로 간다.

이미 `LIVE`인 방에 들어오면(새로 고침, 두 번째 면접관) 2번을 건너뛰고 바로 붙는다. `ENDED`면 평가 화면으로 보낸다.

`feedback1118`이 켜졌을 때 달라지는 것:

- 화상 면접(`mode: ONLINE`)의 "면접 시작" 덮개에는 "이 노트북의 마이크를 사용" 선택이 없다. 화상 회의의 소리를 받는 방식은 아직 확인 중이라고 안내한다([open-questions.md](open-questions.md)).
- 종료 확인 창은 "보고서 초안"만 말한다(AI 참고 평가는 면접관에게 보이지 않기 때문이다).

`persona` 스위치가 켜져 면접에 페르소나가 있으면(`interview.persona`) 위쪽 줄의 면접 종류 옆에 그 이름이 붙는다.

## 실시간 기능이 잠긴 면접 (신입 대면)

`liveLocked(interview)`(`lib/features.js`)가 참이면 그 방은 질문 화면으로만 쓴다. 면접 응답(`GET /interviews/{id}`)의 `liveEnabled`가 `false`일 때다(API 명세 2.5). 화면은 트랙이나 스위치, 환경변수를 보지 않는다.

- 실제 백엔드에 붙으면 백엔드가 값을 정한다. 명세 2.5: 신입(대면) 면접은 기본이 `false`이고 백엔드 설정으로 연다.
- 가짜 데이터에서는 모의 서버(`mocks/server.js`의 `liveLocked`)가 정한다: `feedback1118`이 켜져 있고(4주 차 이후 목업, `npm run dev`) 면접자 트랙이 신입(`NEW_GRAD`)이면 `false`. 빌드 환경변수 `VITE_NEW_GRAD_LIVE=on`이면 `true`로 준다.

잠긴 방에서 달라지는 것:

- "면접 시작"은 `POST /rooms/{id}/start`만 부른다. 입장권을 받지 않고, Agent에 붙지 않고, 마이크를 켜지 않는다(`goLive`). 이런 면접에 입장권을 요청하면 백엔드는 `409 LIVE_DISABLED`로 답한다(API 명세 2.7).
- 위쪽 줄에 화자 전환, 연결 표시, 마이크 버튼, "대화 펼치기"가 없다. "실시간 기록 잠김" 배지와 "면접 종료"만 있다.
- 가운데 나무에는 준비된 질문과, 면접 전에 만든 예상 꼬리질문(부모가 있는 `FOLLOW_UP` 질문, `parentQuestionId`)이 가지로 보인다. "꼬리질문 지금 만들기" 버튼은 없다. 물은 질문은 눌러서 표시한다.
- 대화 칸과 "방금 들은 말" 줄, 노란 안내 줄이 나오지 않는다. 숫자 키 `1`~`3`과 `M`도 동작하지 않는다.
- 메모 자동 저장과 "면접 종료"(`POST /rooms/{id}/end`)는 같다. 종료 확인 창은 보고서를 만들지 않는다고 알린다. 면접 후 화면에는 보고서 대신 "이 면접은 보고서를 만들지 않습니다"가 나오고, AI 참고 평가·대화 기록 탭이 없다.

예상 꼬리질문의 글은 Agent가 만들어야 하는데 아직 주지 않는다(API 명세 4.1). 그때까지 실제 백엔드에 붙으면 받은 예상 꼬리질문이 없어 가지가 보이지 않는다([open-questions.md](open-questions.md)).

## 끊겼을 때

- 소켓이 예기치 않게 닫히면 1.6초부터 최대 8초 간격으로(1.6 → 3.2 → 6.4 → 8) 다시 붙는다. 입장권은 5분짜리라 매번 새로 받는다.
- 다시 붙으면 `ready.lastSeq`와 내 마지막 seq를 비교해, 놓친 구간을 백엔드 `GET /rooms/{id}/utterances?afterSeq=`로 채운다.
- 닫힘 코드 4409(마이크 단말 중복)면 듣기 전용으로 바꿔 다시 붙는다. 4401(인증 실패)·1000(정상)은 다시 붙지 않는다.
- 네트워크가 밀려 보낼 오디오가 2초 분량(64,000바이트) 넘게 쌓이면 새 프레임을 버린다(지연이 계속 늘어나는 것보다 낫다).
- 연결이 끊겨도 메모는 백엔드 REST로 저장되므로 계속 쓸 수 있다. 화면 위에 노란 안내 줄이 뜬다.
- 모델이 멈췄을 때도 같은 줄에 알린다(`room-state.js`의 `statusNotice`). `status` 이벤트의 값이 풀릴 때까지 계속 떠 있다.

  | 상태 | 안내 | 면접관이 할 일 |
  | --- | --- | --- |
  | `stt: DOWN` (연속 실패) | 음성 인식이 멈췄다. 음성은 계속 받고 있어 면접 뒤에 글로 바뀐다 | 면접을 계속하고 메모를 쓴다 |
  | `llm: DOWN` | 꼬리질문 제안과 문장 다듬기가 멈췄다 | 준비한 질문으로 진행한다 |
  | `stt: DEGRADED` (직전 실패·밀림) | 글이 늦게 나타난다 | 없음 |
  | `llm: DEGRADED` | 알리지 않는다 | 없음 |

## 화자 구분 (면접관 / 지원자)

Whisper는 화자를 나누지 못한다. 화면이 하는 일은 세 가지다.

1. **자동(기본)**: Agent가 판정한다(준비된 질문과의 유사도 → 규칙 → LLM 문맥). 근거는 `speakerMethod`로 오고 화자 배지의 툴팁에 보인다.
2. **수동 전환**: 위쪽의 `자동 | 면접관 | 지원자`(Alt+1/2/3). 누르면 `{ type: "role" }`을 보내고, 그 뒤의 말은 그 화자로 기록된다. 자동 판정이 자꾸 틀리는 방에서 쓴다.
3. **사후 고치기**: 대화에서 화자 배지를 누르면 반대 화자로 바뀐다(`utterance.fix`). 평가·보고서는 고친 화자를 쓴다.

전체 대응책 비교는 상위 `docs/04-speaker-separation.md`와 agent 레포의 `docs/speaker-separation.md`.

## 질문과 꼬리질문 나무 (`feedback1118`이 켜졌을 때)

가운데 칸(`QuestionTreePane.vue`)은 준비된 질문을 줄기로, 꼬리질문을 그 아래의 가지로 보여 준다. 묶는 일은 `room-state.js`의 `questionTree(questions, followUps, utterances)`가 한다.

- **줄기**: 부모가 없고 출처가 `FOLLOW_UP`이 아닌 질문(준비된 질문, 직접 추가한 질문). 번호는 줄기에만 붙는다.
- **가지**는 세 가지다.
  - 면접 전에 만든 예상 꼬리질문: `parentQuestionId`가 가리키는 질문 아래.
  - 면접 중 제안된 꼬리질문(`followup.suggested`): 제안의 근거가 된 발화(`basedOnSeq`) 전에 가장 늦게 물은 질문 아래. 누르면 채택한다.
  - 채택한 꼬리질문(질문 목록에 올라간 `FOLLOW_UP` 질문): 같은 글의 제안 자리에 제안 대신 보인다. 말로 물어 채택된 것에는 "말로 물어 자동으로 채택됨"이 붙는다.
- **꼬리의 꼬리**: 방금 물은 것이 채택한 꼬리질문이면, 그 답에서 나온 제안은 그 꼬리질문 아래에 한 단계 더 들여 쓴다. `flattenBranches`가 가지를 그릴 순서대로 펴고 들여 쓸 단계(`depth`)를 준다.
- **"언제 어느 질문을 물었는지"**는 세 군데에서 모은다: 발화의 `matchedQuestionId`, 질문의 `askedAtSeq`(손으로 표시하면 `use-room.js`의 `toggleAsked`가 그때의 마지막 seq를 적는다), 말로 물어 채택된 제안의 `spokenAtSeq`. 발화 기록을 같이 보기 때문에 질문을 준비한 순서와 다르게 묻거나 같은 질문을 나중에 다시 물어도 앞서 붙은 가지의 자리가 바뀌지 않는다.
- 물은 질문이 아직 없어 붙일 곳이 없는 제안은 맨 아래 "질문과 이어지지 않은 꼬리질문"에 모인다(`loose`).
- 방금 물은 질문이 있는 줄기에 "지금 질문" 표시가 붙고(`currentId`), 그 질문과 새로 붙은 가지가 보이도록 스크롤한다.
- 위쪽의 "남은 것만"을 켜면 물은 줄기를 숨긴다(지금 질문은 남긴다). 아래의 입력 칸으로 질문을 직접 추가한다.

이 동작의 테스트는 `room-state.test.js`에 있다(순서를 바꿔 묻기, 다시 묻기, 꼬리의 꼬리, 예상 꼬리질문, 붙일 곳이 없는 제안).

## 지원자 요약과 메모 (`feedback1118`이 켜졌을 때)

왼쪽 칸의 위는 `CandidateBrief.vue`, 아래는 내 메모다. 요약은 접을 수 있고 탭 세 개로 나뉜다.

| 탭 | 보이는 것 |
| --- | --- |
| 요약 | 한 줄 소개, 핵심, 강점, 확인할 점이 몇 개 남았는지 |
| 확인할 점 | 확인할 점마다 근거가 된 문장과 그것을 확인하는 준비된 질문. 질문을 누르면 가운데 칸의 그 질문으로 가고, 그 질문을 물었으면 체크된다. 앞 차수에서 넘어온 확인점이 있으면 맨 위에 보인다 |
| 이력 | 기간순 이력, 요약과 질문에서 제외한 항목(블라인드) |

- 근거 문장과 질문 연결은 사전 리포트의 `summary.checkItems`, 앞 차수 확인점은 `previousRoundChecks`에서 읽는다(둘 다 API 명세 2.6). `checkItems`는 선택 항목이고 Agent가 아직 주지 않는다([open-questions.md](open-questions.md)). `checkItems`가 없으면 글만 있는 `summary.checkPoints`를 보여 준다. `previousRoundChecks`는 백엔드가 채운다.
- 사전 리포트의 요약이 없으면 요약 칸 없이 메모만 나온다.

## 대화와 "방금 들은 말" (`feedback1118`이 켜졌을 때)

- 대화는 접혀 있다. 위쪽 줄의 "대화 펼치기"를 누르면 오른쪽에 `TranscriptPane`이 열리고, "대화 접기"로 닫는다.
- 접혀 있는 동안 가운데 칸 아래에 "방금 들은 말"이 한 줄로 나온다: 임시 글자(`transcript.partial`)가 있으면 그것을, 없으면 마지막 발화의 화자와 문장을 보여 준다. 이 줄을 눌러도 대화가 펼쳐진다.
- 화자 배지를 눌러 고치는 것(사후 고치기)은 대화를 펼쳐야 할 수 있다.

## 질문 목록 (`feedback1118`이 꺼졌을 때)

왼쪽 칸은 질문을 **한 목록**에 출처 순서대로 보여 준다: 이력서 → JD → 질문 은행 → 추가(면접 중 올린 꼬리질문과 직접 추가한 질문). 출처가 바뀌는 자리에 구역 제목과 `물은 수/전체`가 있고, 스크롤해도 지금 구역의 제목이 위에 붙어 있다. 번호는 목록 전체에서 이어진다. 질문이 자동으로 인식되거나 새로 추가되면 그 질문이 보이도록 스크롤한다. 구역 정의와 순서는 `QuestionPane.vue`의 `GROUPS`.

| `1` `2` `3` | 최신 꼬리질문 후보를 질문 목록에 올린다(입력 칸에 있을 때는 동작 안 함). 나무 배치에서는 가장 최근 제안 묶음의 가지에 같은 숫자가 보인다 |
| `Alt+1` `Alt+2` `Alt+3` | 화자: 자동 / 면접관 / 지원자 |
| `M` | 마이크 끄기·켜기 |

실시간 기능이 잠긴 면접에서는 `1` `2` `3`과 `M`이 동작하지 않는다.

## 노트북 화면 규칙

- 페이지 스크롤이 없다(`h-screen overflow-hidden`). 칸이 각자 스크롤한다.
- 칸 너비(`feedback1118`이 켜졌을 때): 대화를 접었으면 왼쪽 24%(최소 260px) · 가운데 나머지. 펼쳤으면 왼쪽 20%(최소 230px) · 가운데 나머지 · 오른쪽 30%(최소 300px). 잠긴 면접은 늘 두 칸이다.
- 칸 너비(`feedback1118`이 꺼졌을 때): 왼쪽 22%(최소 250px) · 가운데 나머지 · 오른쪽 26%(최소 280px). 1366px에서 가운데가 약 700px이다.
- 나무 배치에서는 줄기 질문의 글자가 가장 크다(1.08rem). 가지는 그보다 작다(0.97rem). 지원자 요약은 화면 높이의 40%까지만 차지하고 그 안에서 스크롤한다.
- 대화에서는 지원자 답변 글자가 가장 크다(1.08rem). 면접관 질문은 작고 흐리게 한다. 면접관이 봐야 하는 것은 답변이기 때문이다.
- 대화는 새 글을 따라 내려가다가, 사용자가 위로 올리면 멈추고 "최신 대화로" 버튼이 뜬다.

## 모의 모드

`mocks/socket.js`가 `mocks/data.js`의 대본을 재생한다. 방의 면접자 트랙에 따라 신입은 `liveScript`, 경력은 `liveScriptExperienced`(화상 직무 면접)다(`scriptFor`). 마이크 권한이 없어도(또는 막힌 환경에서도) 대본은 흐른다. 실제 Agent와 다른 점: 오디오 내용을 듣지 않는다, 지연이 일정하다.

- 경력 대본에는 꼬리질문 후보를 말로 묻는 장면과, 준비한 순서와 다르게 묻는 장면(질문 4를 질문 3보다 먼저)이 있다. 나무에서 가지가 제자리에 붙는지 볼 때 쓴다.
- 실시간 기능이 잠긴 면접(모의 서버가 `liveEnabled: false`를 주는 신입 면접)은 소켓에 붙지 않으므로 대본이 돌지 않는다. 모의 서버가 그 면접의 질문에 예상 꼬리질문을 3개씩 붙여서 준다(`data.js`의 `questionsFor`에 `predicted`).
