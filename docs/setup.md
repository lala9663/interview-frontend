# 설치와 실행

## 필요한 것

- Node.js 24 (npm 11 포함). 확인: `node -v`, `npm -v`

## 설치

```bash
npm ci
```

사내망에서는 npm 레지스트리를 사내 미러로 바꾼 뒤 실행한다(`.npmrc`에 `registry=` 한 줄). `package-lock.json`을 함께 반입해 같은 버전이 깔리게 한다.

## 실행 방식 네 가지

| 명령 | 모드 | 필요한 것 | 주소 |
| --- | --- | --- | --- |
| `npm run dev` | mock | 없음 | http://localhost:5173 |
| `npm run dev:api` | api | 백엔드 8080, Agent 8000 | http://localhost:5173 |
| `npm run build` → `dist/` | api | 웹 서버(같은 도메인에서 `/api/v1`을 백엔드로 넘김) | 배포 주소 |
| `npm run build:demo` → `dist-demo/interview-mockup-<주차>.html` (주차마다 하나) | mock | 없음(서버도 필요 없다) | 파일을 더블클릭 |

2026-11-18 현업 회의 의견을 반영한 화면(경력 탭 먼저, 면접 방의 새 배치, 면접 페르소나, 시스템 상태, 일정 달력 등)은 API 명세에 들어가 있어 네 방식 모두에서 켜진다(3주 차 목업 파일만 예외다). mock 모드(`npm run dev`, `build:demo`)에서만 켜지는 것은 API 명세에 아직 없는 화면 시안뿐이다: 관리 > AI 모델, 그리고 관리 > 등록의 "매칭 파일 올리기"·"채용 시스템에서 불러오기". `npm run dev:api`와 `npm run build`에서는 관리 > AI 모델이 없고 관리 > 등록 · 매칭에 임시 자동 매칭이 나온다. 아래 "가짜 데이터로 돌 때만 켜지는 화면" 참고.

### 시연용 HTML (`build:demo`)

화면 전체를 HTML 한 파일로 만든다. 스크립트·스타일·글꼴이 모두 들어 있어 서버 없이 브라우저로 바로 열리고, 메일이나 메신저로 보낼 수 있다(약 4MB).

- 데이터는 전부 가상이고 `src/mocks/`가 답한다. 새로 고침하면 처음 상태로 돌아간다.
- 오늘 일정은 여는 시각을 기준으로 잡힌다. 언제 열어도 "곧 시작할 면접"과 "진행 중인 방"이 있다.
- 면접 방은 마이크를 요청하지 않고 대본을 흘려보낸다(`.env.demo`의 `VITE_MOCK_MIC=off`). 실제 마이크 동작은 이 파일로 확인할 수 없다.
- 면접 방 위쪽에 설명 띠가 나온다(`VITE_DEMO_GUIDE=on`, `features/room/DemoGuide.vue`). 지금 시스템이 하는 일(음성을 글로 → 문장 다듬기·화자 구분 → 준비한 질문 찾기 → 꼬리질문 만들기)을 보여 주고, 멈춤·2배·처음부터 버튼이 있다. "처음부터"는 화면을 새로 읽어 모의 데이터를 처음 상태로 되돌린다. 실시간 기능이 잠긴 방(아래)에는 나오지 않는다.
- 대본은 `src/mocks/data.js`에 둘 있다: 신입 `liveScript`, 경력 화상 직무 면접 `liveScriptExperienced`(각 문장 18개, 1배속으로 약 2분 30초). 방의 면접자 트랙에 맞는 것이 나온다(`scriptFor`). 대본의 `q`는 준비된 질문의 순서와 맞춰야 자동 체크가 된다.
- 경력 대본에는 꼬리질문 후보를 누르지 않고 말로 묻는 장면과, 준비한 순서와 다르게 묻는 장면(질문 4를 질문 3보다 먼저)이 들어 있다. 묻는 순서는 대본 위의 주석에 적혀 있다.
- 4주 차 목업부터 처음 열리는 위쪽 탭은 경력 채용이다. 시연에서 들어갈 방은 경력 화상 직무 면접(1차)이다. 신입도 경력도 면접은 직무(1차)·인성(2차) 두 가지뿐이다.
- 4주 차 목업부터 신입 면접 방은 실시간 기능이 잠겨 있어 대본이 돌지 않는다. 모의 서버(`mocks/server.js`)가 신입 면접의 `liveEnabled`를 `false`로 주고, 화면은 그 값을 본다(`lib/features.js`의 `liveLocked`). 마이크·Agent 연결 없이 질문 화면으로만 열리고, 질문마다 예상 꼬리질문 3개가 가지로 붙는다. 면접을 끝내도 보고서는 만들어지지 않는다. 풀어서 보려면 `VITE_NEW_GRAD_LIVE=on`으로 빌드한다(이 환경변수는 모의 서버만 읽는다).
- 면접 페르소나를 바꾸면 준비된 질문의 표현이 바뀐다(모든 면접). 경력 직무 면접은 페르소나마다 따로 써 둔 표현을 쓰고(`data.js`의 `PERSONA_TEXT`), 그 밖의 면접(신입, 인성 면접)은 원래 질문 뒤에 페르소나의 요구를 덧붙인다(`personaRewrite`). 표준 구조화형과 관리자가 더한 페르소나는 원래 표현 그대로다.
- 관리 > 등록의 "매칭 파일 올리기"(신입)와 "지금 불러오기"(경력)는 파일을 고르거나 채용 시스템에 붙지 않는다. 모의 서버의 배정 기능을 대신 부른다. API 명세에 아직 없는 화면 시안이다(명세 2.14).
- 시스템 상태(위쪽 줄의 상태 버튼, 관리 > 시스템 상태)의 값은 `data.js`의 `systemStatus()`가 주는 고정된 가짜 값이다. 모양은 API 명세 2.13과 같다. LLM이 "지연"으로 나오게 되어 있다.
- 관리 > AI 모델의 모델 목록과 작업별 모델은 `data.js`의 `aiModels`, `aiModelTasks`다. 모델은 Gemma 4, 가우스, DS Assistant, Whisper large-v3 네 개다. 어느 작업이 어느 모델을 쓰는지와 상태는 가짜 값이고, 바꿔도 기록만 남을 뿐 다른 화면의 동작은 달라지지 않는다. API 명세에 아직 없는 화면 시안이다(명세 2.14).
- 면접 후의 질문 피드백("준비된 질문은 도움이 됐나요?")은 모의 서버가 메모리에 저장한다(사람마다 면접 한 건에 하나). 다시 들어가면 남긴 의견이 보이고, 새로 고침하면 다른 가짜 데이터와 함께 처음 상태로 돌아간다.
- 주소는 `#` 뒤로 화면을 구분한다(`VITE_ROUTER=hash`). 서버가 없어서다.
- 설정은 `vite.config.js`의 `demo` 부분과 `.env.demo`에 있다.

여덟 파일 모두 2026-11-19에 지금 코드로 다시 빌드했다. 주차는 공통 문서 `10-roadmap.md` 3장의 일정(1단계 개발이 끝나는 10주 차까지)을 따른다. 5주 차 뒤의 주차에 무엇을 보여 줄지는 그 주의 일이 정해지면 `changelog.js`와 `features.js`를 고쳐 다시 빌드한다.

- **코드는 한 벌이다.** 기능은 모두 만들어져 있고, 주차별 목업에서만 그 주차에 보여 줄 기능을 켠다. 개발 서버(`npm run dev`)와 실제 배포 빌드에서는 주차가 없으므로 모든 기능이 켜진다. 예외는 아래 "가짜 데이터로 돌 때만 켜지는 화면"의 `modelSwitch` 스위치다.
- **어느 주차에 무엇을 켜는지**는 `src/lib/features.js`의 표에 있다(기능 이름 → 처음 보이는 과제 주차). 화면·메뉴·라우트(`meta.feature`)·모의 서버가 `has('이름')`으로 확인한다. 가려진 화면의 주소로 직접 들어가면 오늘(또는 관리 > 등록·매칭)으로 돌아간다.
- **주차 목록과 변경 요약**은 `src/mocks/changelog.js`에 있다. 목업의 로그인 화면과 위쪽 줄에 "N주 차 · 달라진 것" 버튼이 나오고(`components/DemoChangelog.vue`), 누르면 그 주차까지의 변경 요약이 뜬다. 이 버튼은 목업에만 나온다.
- 주차 이름은 `main`에 붙이는 태그와 같다(예: `2026-w47`). 가장 최근 주차는 `interview-mockup.html`로도 나온다.
- 한 주차만 다시 만들려면 `npm run build:demo -- 2026-w48`. 빌드 스크립트는 `scripts/build-mockups.mjs`다.
- 주차 이름이 붙은 파일은 git에 올린다(빌드 없이 받아서 바로 열 수 있게). `interview-mockup.html`은 사본이라 올리지 않는다(`.gitignore`). 한 파일이 약 4MB다.

바꿀 때:

- **주차에 넣을 기능을 옮긴다**: `features.js`의 번호와 `changelog.js`의 항목을 같이 고치고 다시 빌드한다.
- **새 기능을 만들었다**: 어느 주차에 보여 줄지 정해 `features.js`에 이름을 더하고 화면에서 `has()`로 감싼다. `changelog.js`의 그 주차에 한 줄 적는다. 적지 않으면 처음(3주 차) 목업부터 보인다.
- **주차를 더한다**(11주 차 이후): `changelog.js` 맨 위에 항목을 더한다.
- 이미 회의에서 보여 준 주차의 파일과 변경 요약은 바꾸지 않는다. 현업 의견으로 고친 것은 다음 주차의 "개선"·"수정"으로 적는다.

### 가짜 데이터로 돌 때만 켜지는 화면

`features.js`의 `MOCKUP_ONLY`에 든 스위치는 주차 조건에 더해 "가짜 데이터로 도는 빌드"여야 켜진다. 주차별 목업(`VITE_DEMO_WEEK`가 있음)이거나 `VITE_API_MODE=mock`일 때다(`features.js`가 내보내는 `mockData`). API 명세에 아직 없는 것만 여기에 두고, 지금은 `modelSwitch` 하나다(명세 2.14).

스위치 없이 `mockData`를 직접 보는 곳이 하나 더 있다. 관리 > 등록의 "매칭 파일 올리기"·"채용 시스템에서 불러오기"는 `feedback1118`이 켜져 있고 `mockData`일 때만 나온다(`features/admin/SetupPage.vue`, 탭 이름은 `AdminTabs.vue`). 이것도 API 명세에 아직 없다(명세 2.14).

2026-11-18 회의 의견을 반영한 스위치는 다섯이고, 모두 처음 보이는 주차가 4주 차다.

| 스위치 | 켜지면 보이는 것 | 실제 백엔드에 붙는 빌드 |
| --- | --- | --- |
| `feedback1118` | 경력 채용 탭이 먼저(처음 여는 탭도 경력), 면접 방의 새 배치([realtime-room.md](realtime-room.md)), 면접 전의 "질문 전체 다시 만들기"(질문을 하나씩 빼고 더하는 것은 숨김), 면접 후의 질문 피드백과 "의견 초안 넣기", AI 참고 평가 탭은 관리자만, 면접자 목록의 "면접자 엑셀 업로드" 버튼(관리자)과 면접자 유형 거르기, 면접자 유형 배지, 면접 종류를 고르는 곳은 신입도 경력도 직무·인성 두 가지 | 켜짐 |

| `npm run dev:api`, `npm run build` | 켜짐 | 꺼짐 |

- 실제 백엔드에 붙는 빌드에서 이 화면들이 쓰는 값과 경로는 API 명세에 있고 백엔드가 답한다(API 명세 2.3, 2.5, 2.6, 2.7, 2.8, 2.12, 2.13). API 명세에 아직 없는 것과, 명세에는 있지만 Agent가 아직 주지 않는 것은 [open-questions.md](open-questions.md)의 "API 명세에 아직 없는 화면 시안"에 모아 두었다.
- 실시간 기능 잠금은 `liveLocked(interview)`가 정한다: 면접 응답의 `liveEnabled`가 `false`면 잠근다(API 명세 2.5). 화면은 트랙이나 환경변수를 보지 않는다. 실제 백엔드에 붙으면 백엔드가 그 값을 정한다(명세 2.5: 신입 대면 면접은 기본이 `false`). 가짜 데이터에서는 모의 서버(`mocks/server.js`)가 정한다: `feedback1118`이 켜져 있고 트랙이 신입(`NEW_GRAD`)이면 `false`, 빌드 환경변수 `VITE_NEW_GRAD_LIVE=on`이면 `true`.

세 레포를 함께 띄우는 순서: 백엔드(`./gradlew bootRun`) → Agent(`.venv/Scripts/python -m uvicorn app.main:app --port 8000`, 리눅스는 `.venv/bin/python`) → 프론트(`npm run dev:api`). Agent는 환경변수 `BACKEND_MODE=http`로 띄워야 전사·꼬리질문이 백엔드에 저장된다. Agent의 기본값은 `fake`(가짜 백엔드)라, 그대로 띄우면 데모 방 정보를 쓰고 저장 요청을 로그로만 남긴다. 설정 표는 agent 레포 `docs/setup.md` 3장에 있다. 자세한 것은 각 레포의 `docs/setup.md`.

## 마이크

- 브라우저의 마이크 권한이 필요하다. `localhost`와 HTTPS에서만 동작한다(사내 배포는 HTTPS여야 한다).
- Chrome·Edge 기준으로 만들었다.

## 배포할 때 웹 서버가 해 줘야 하는 것

- `dist/`를 정적 파일로 제공하고, 없는 경로는 `index.html`로 돌려준다(history 라우팅).
- `/api/v1/**` → 백엔드로 프록시.
- Agent WebSocket 주소는 백엔드가 입장권과 함께 알려 준다(백엔드 환경변수 `AGENT_WS_BASE_URL`). 프록시가 WebSocket 업그레이드를 허용해야 한다.

## 자주 나는 문제

| 증상 | 원인과 해결 |
| --- | --- |
| `MOCK_ROUTE_MISSING` 토스트 | `api/index.js`에 더한 경로가 `mocks/server.js`에 없다 |
| 로그인 뒤 바로 로그인 화면으로 | 백엔드가 401. `VITE_API_BASE_URL`과 백엔드 CORS 허용 주소(5173) 확인 |
| `npm run build`가 "modules transformed" 뒤에 아무 말 없이 끝난다(두 번째 빌드부터) | 프로젝트가 OneDrive 동기화 폴더 안에 있을 때 Node가 기존 `dist/`를 지우다 죽는다. `dist/` 폴더를 탐색기나 셸에서 지우고 다시 빌드하거나, 프로젝트를 OneDrive 밖(예: `C:\work`)에 둔다. 사내 PC·서버에서는 해당 없음 |
| 면접 방에서 "연결 중"이 계속 | Agent가 꺼져 있거나 입장권 비밀키(`ROOM_TICKET_SECRET`)가 백엔드와 다르다 |
| `The 'bg-…' class does not exist` | Tailwind 설정을 못 찾음. `postcss.config.js`가 설정 경로를 절대 경로로 넘기는지 확인 |
