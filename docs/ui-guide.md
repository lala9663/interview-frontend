# 화면 디자인 규칙

> 다루는 것: 노트북에서 한눈에 들어오게 하려고 정한 것들. 화면을 더하거나 고칠 때 따른다.

## 방향

서비스 이름은 **DSInterview**다. 업무용 도구처럼 보이게 한다: 꾸밈보다 글과 정보가 먼저 보인다.

- 바탕은 흰색 한 가지다. 구역은 카드와 그림자가 아니라 가는 선과 여백으로 나눈다.
- 주 색은 파란색(`brand`) 하나다. 주 버튼, 선택 상태, 링크에만 쓴다.
- 모서리는 작게: 카드 `rounded-lg`(8px), 버튼·입력 `rounded-md`(6px), 배지 `rounded`(4px). `rounded-xl` 이상은 쓰지 않는다. 동그라미(`rounded-full`)는 점과 사람 표시에만.
- 그림자는 떠 있는 것(모달, 토스트, 떠 있는 버튼)에만 `shadow-pop`.
- 숫자(시각, 점수, 건수)는 `tabular-nums`로 자릿수를 맞춘다.
- 되풀이해 쓰는 모양:
  - 구역 제목: `h-sec` 아래에 가는 선(`border-b border-line pb-2`). 글만 있는 구역은 카드로 감싸지 않는다. 표와 필터가 붙은 목록만 `.card`로 감싼다.
  - 숫자 요약: 칸마다 카드로 만들지 않고 세로선(`border-l border-line`)으로 나눈 한 줄.
  - 고르는 것(필터, 하위 메뉴): 채운 버튼이 아니라 밑줄 탭(`.tab` / `.tab-on`). 켜고 끄는 필터 버튼은 켜졌을 때 `border-ink bg-sunken`.
  - 켜고 끄는 설정(저장되는 값): `components/ToggleSwitch.vue`. 값은 부모가 들고, `label`은 꼭 준다(화면에 글자가 없어 `aria-label`로 쓰인다). 관리 > 면접 페르소나의 추천·사용 칸이 쓴다.
  - 여러 개 가운데 하나를 고르는 카드(면접 전의 페르소나): 고른 것은 `border-brand bg-brand-soft/40`, 나머지는 `border-line`. 면접 방의 "지금 질문"도 같은 표시다.
  - 강조·경고·AI가 만든 글: 색 면이 아니라 왼쪽 세로선(`border-l-2 border-ok|warn|bad|brand pl-3.5`).

## 기준 화면

- **1366×768**(가장 작은 사내 노트북)에서 가로 스크롤이 없고, 핵심 동작 버튼이 첫 화면에 보여야 한다. 1440×900, 1920×1080에서도 확인한다.
- 본문 최대 너비 1280px. 왼쪽 메뉴는 76px 고정(아이콘 + 짧은 이름)으로 본문 폭을 아낀다.
- 기본 글자 15px(`html { font-size: 15px }`). 본문은 0.93rem 이상, 보조 정보도 0.76rem 아래로 내려가지 않는다.

## 색 (토큰)

`styles/main.css`의 `:root`(밝은 화면)와 `.dark`에 CSS 변수로 있고 `tailwind.config.js`가 이름을 잇는다.

| 이름 | 쓰는 곳 |
| --- | --- |
| `bg` / `surface` / `sunken` | 바탕 / 카드 / 눌린 면(입력 묶음, 표 머리) |
| `line` | 테두리, 구분선 |
| `ink` / `sub` / `faint` | 본문 / 보조 글 / 가장 흐린 글(시각, 라벨) |
| `brand` (+`soft`, `ink`) | 주 버튼, 선택 상태, 링크. 파란색 |
| `ok` / `warn` / `bad` / `live` (+`soft`) | 완료·좋음 / 대기·주의 / 실패·오류 / 진행 중·녹취 중 |

- 뜻이 있는 색만 쓴다. 장식용 색을 더하지 않는다.
- 상태는 색만으로 구분하지 않는다. 항상 글자(배지)와 함께 쓴다.
- 새 색이 필요하면 변수 두 벌(밝은·어두운)을 함께 더한다.

## 공용 클래스

| 클래스 | 설명 |
| --- | --- |
| `.card`, `.card-pad` | 테두리만 있는 면(그림자 없음). 꼭 묶어 보여야 하는 것에만 쓰고, 목록은 카드 없이 줄(`.row-line`)로 둔다 |
| `.btn` + `.btn-primary` `.btn-danger` `.btn-ghost` + `.btn-sm` `.btn-lg` `.btn-icon` | 버튼. 화면마다 주 버튼(`btn-primary`)은 하나만 |
| `.input` | 입력·textarea |
| `.badge` + `.tone-neutral|brand|ok|warn|bad|live` | 상태 배지: 색 점 + 글자(색 면을 깔지 않는다). 점은 `.badge`가 그리므로 안에 점을 따로 넣지 않는다. 보통 `StatusBadge` 컴포넌트로. 배지가 아닌 곳에 `tone-*`만 붙이면 옅은 면 + 같은 색 글자가 된다 |
| `.label`, `.h-page`, `.h-sec` | 작은 라벨, 페이지 제목, 구역 제목 |
| `.tab`, `.tab-on` | 탭 |
| `.row-line`, `.th`, `.td` | 목록·표의 줄 |
| `.kbd` | 단축키 표시 |

## 배치 원칙

1. **한 화면에 한 가지 주 동작.** "오늘"은 다음 면접 입장, "면접 전"은 면접 방 입장, "면접 후"는 평가 제출.
2. **흐름이 보이게.** 면접 한 건의 화면에는 항상 `면접 전 → 면접 중 → 면접 후` 단계 표시를 둔다.
3. **AI가 만든 것과 사람이 쓴 것을 나눈다.** AI의 제안·근거는 색 면 대신 왼쪽 세로선(`border-l-2`)으로 표시한다. 면접 후 화면은 왼쪽이 AI(보고서·참고 평가), 오른쪽이 내 평가다. AI 점수는 내 점수를 넣은 항목만 보여 준다. 화면 시안(`feedback1118`)이 켜졌을 때는 내 평가 칸에 AI 점수를 보여 주지 않고, AI 참고 평가 탭은 관리자에게만 보인다. 면접 방의 나무에서 아직 채택하지 않은 AI 제안은 `text-brand` 글자로, 질문 목록에 있는 질문은 본문 색으로 구분한다.
4. **기다림을 숨기지 않는다.** AI 작업 중에는 무엇을 하는 중이고 얼마나 걸리는지 문장으로 적는다. 초안과 보정본을 배지로 구분한다.
   - 시스템 상태도 같은 원칙이다. 위쪽 줄의 상태 버튼(`components/SystemStatusChip.vue`)은 가장 나쁜 상태 하나를 글자와 색(`lib/labels.js`의 `SYSTEM_STATUS`: 정상 `ok` · 지연 `warn` · 멈춤 `bad`)으로 보여 주고, 정상이 아니면 꼬리질문을 기다리는 시간을 함께 적는다. 기다리는 시간은 평소 값과 나란히 적고, 평소의 1.5배를 넘으면 `text-warn`이다(`SystemStatusPanel.vue`).
5. **빈 화면에는 다음에 할 일을 적는다**(`EmptyState`).
6. **착각을 막는다.** 내 평가 칸 위에는 "공식 평가는 채용 시스템에 입력" 안내를 늘 둔다.

## 숫자와 막대 (관리 화면)

- 숫자가 주인공이면 차트 대신 숫자 칸을 쓴다. 막대는 비교가 필요한 곳에만.
- 양쪽으로 갈리는 값(편차)은 `features/admin/DivergingBar.vue`: 가운데가 0, 양수는 오른쪽 `pole-a`, 음수는 왼쪽 `pole-b`. 값은 늘 숫자로도 적는다.
- `ok / warn / bad / live`는 상태에만 쓴다. 막대의 계열 색으로 쓰지 않는다(막대는 `brand` 한 색).
- 비교 건수가 적은 값은 흐리게 보이고, 몇 건 기준인지 함께 적는다.

## 접근성

- 버튼은 `<button>`, 이동은 `<RouterLink>`. 아이콘만 있는 버튼에는 `aria-label`.
- 키보드 초점 표시(`focus-visible` 링)를 지우지 않는다.
- 모달은 Esc와 바깥 클릭으로 닫힌다.
